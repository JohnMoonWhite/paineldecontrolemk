# Monitoring Foundation and OrdemSync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first safe, deployable vertical slice of the partners' monitoring PWA: protected central access with mandatory 2FA, a five-minute server-side snapshot sync from OrdemSync, and an executive dashboard that never exposes source credentials or source emails.

**Architecture:** A React PWA reads only consolidated `monitoring_` tables in the existing central Supabase project. A private Edge Function normalizes read-only OrdemSync records and writes an atomic snapshot; scheduled server invocations call it every five minutes. Supabase Auth plus an application allow-list and MFA assurance level 2 protect the app.

**Tech Stack:** React, TypeScript, Vite, vite-plugin-pwa, Vitest, Testing Library, Supabase JS, Supabase Edge Functions (Deno), PostgreSQL, Supabase Auth MFA, Supabase CLI.

**Spec:** docs/superpowers/specs/2026-09-28-painel-controle-design.md

## Global Constraints

- Reuse central Supabase project `egagpdfcyazjuzeofbbl`; do not alter its existing tables or application behavior.
- All tables introduced by this work begin with `monitoring_`.
- The OrdemSync project (`qggkcflrmusfvjqsfhsf`) is read-only. Its credentials live only as Edge Function secrets.
- Do not persist source emails, raw payment payloads, API keys, or service-role credentials in browser code or public tables.
- Use the normalized entity rule: organization subscription records take precedence; an individual profile counts only when it has no active `organization_members` row.
- Display source data as snapshots. A failed sync preserves the previous successful snapshot and marks the source stale after 15 minutes.
- The public dashboard shows stable source identifier and optional display name only.
- Run all database changes through a new Supabase migration generated by the CLI. Do not make schema edits directly in the dashboard.

## Review Focus

- Confirm RLS prevents unauthenticated, non-allow-listed, and AAL1 users from seeing monitoring data.
- Confirm the normalizer never double-counts active organization members as individual subscriptions.
- Confirm a sync failure cannot erase or partially replace the last successful facts.
- Confirm the installable PWA has usable loading, empty, error, and stale-data states.
